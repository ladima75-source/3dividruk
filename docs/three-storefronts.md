# Три тематичні вітрини 3DiViDruk — єдина система (тестовий етап)

## Принцип

**Одна база товарів, одна центральна адмінка, три тематичні сайти.**

| ID | Майбутній домен | Публічний тестовий маршрут | Категорії | Товарів у вихідному знімку |
|---|---|---|---|---:|
| `svitlo` | `svitlo.3dividruk.com.ua` | [Світло](https://ladima75-source.github.io/3dividruk/svitlo/) | `lighting` | 63 |
| `vase` | `vase.3dividruk.com.ua` | [Вази та кашпо](https://ladima75-source.github.io/3dividruk/vase/) | `vases`, `planters` | 85 |
| `decor` | `decor.3dividruk.com.ua` | [Декор](https://ladima75-source.github.io/3dividruk/decor/) | `decor` | 30 |

5 сумок MaGelle залишаються в спільному каталозі, але повністю приховані (`storefront_visible=false`). Пряме редагування товару змінює **один** запис — не окремі копії.

## Спільна адмінка

- [Загальний огляд](../admin/dashboard.html) — всі 183 записи, 178 активних, приховані позиції, стан запуску.
- [Редактор трьох вітрин](../admin/storefronts.html) — перемикач Світло / Vase / Decor, індивідуальні заголовки, герой, добірки, обкладинки категорій, порядок блоків.
- [Порядок товарів](../admin/workbench.html) — сортування за категорією/підкатегорією (зміни спільні для всіх вітрин).
- [Спільна медіатека](../admin/media.html) — порядок фото та обкладинки товару.
- [Каталог / ціни / тестові замовлення](../admin/index.html) — одні записи й одна адмін-система.

Файли конфігурації:
- `data/storefronts.json` — до якого магазину належить категорія; майбутні домени (лише план, НЕ активовані).
- `data/storefront-homepages.json` — три окремі дизайни головних сторінок з тим самим форматом, що й базова `data/homepage.json`.
- `data/catalog.json` — спільне джерело цін, SKU, фото й категорій.
- `config/storefront-visibility.json` — пауза для сумок.
- `js/store.js` — одна програма, яка читає `data-storefront`, обмежує категорії і вмикає потрібні тексти.
- `admin/storefronts.js` — редактор спільної адмінки.

## Чернетки і публікація

На GitHub Pages зміни залишаються **лише у локальному браузері**, ключ `3dividruk_admin_draft_v1`. Використовуйте «Експорт JSON» у спільному редакторі. Експорт містить зміни товарів, їх порядок, глобальну головну та всі змінені тематичні головні.

Перевірка: `python tools/apply_editor_draft.py draft.json --check`.

Застосування до тестової збірки: `python tools/apply_editor_draft.py draft.json`; потім `python tools/build.py` і `python tools/validate.py`; перевірити git diff. Нові піддомени, оплата й Нова пошта тут НЕ підключаються.

У майбутньому окремий захищений backend може відповідати на:
- `GET /api/v1/catalog` — повний спільний каталог.
- `GET /api/v1/storefronts` — реєстр вітрин.
- `GET /api/v1/storefront-homepages` — конфігурації трьох вітрин.
- `PATCH /api/v1/admin/storefront-homepages/{slug}` — авторизоване збереження налаштувань окремої вітрини у власну SQLite-базу.

## Домен та SEO — блокування до запуску

**Не змінювати `3dividruk.com.ua`, `www.3dividruk.com.ua` і поточний сайт Prom.ua.** Діючі замовлення та Google Ads залишаються на Prom.

Тестова GitHub Pages збірка має `noindex,nofollow`, а `robots.txt` забороняє індексацію. Це **не парольний захист** — URL може відкрити будь-хто.

GitHub Pages зазвичай використовує одне custom domain налаштування на Pages-сайт. Для трьох незалежних доменів потрібна окрема схема розгортання з трьома hostnames (одна програма з конфігурацією за доменом, або три збірки з єдиного репозиторію) та **одним** захищеним backend.

Перед публікацією: розвести URL товарів по доменах, перевірити canonical, sitemap, Merchant/Meta фіди та GA4 для кожної вітрини; протестувати кошик та передачу `storefront_id` у замовлення; налаштувати HTTPS, CORS і доступ до централізованої адмінки. Поки ці умови не виконані, домени й онлайн-оплати не активувати.
