# 3DiViDruk — робоча адмінка (редактор v1)

## Посилання

- `/admin/dashboard.html` — огляд каталогу, груп, пауз і статусу підготовки до запуску.
- `/admin/workbench.html` — візуальне сортування карток; зміна назви, опису та ціни в діалозі.
- `/admin/index.html#catalog` — наявний розділ каталогу й цін (з авторизованим збереженням, коли backend підключено).
- `/admin/index.html#orders` — тестові замовлення, статуси, ТТН, коли backend підключено.
- `/admin/index.html#settings` — налаштування доставки, оплати та тестового режиму.

## Як пересунути товар

1. Відкрийте **Візуальний редактор**.
2. Виберіть категорію і, коли є, підкатегорію. Порядок зберігається **в межах підкатегорії**.
3. Перетягніть картку мишею або використовуйте кнопки ↑ / ↓.
4. Для зміни назви, тексту опису або ціни натисніть **Редагувати**.
5. Якщо редактор відкритий на GitHub Pages, натисніть **Експорт чернетки JSON** — файл потрібний, щоб перенести локальні правки в репозиторій.
6. Кнопка **Попередній перегляд** відкриває вітрину з параметром `editorPreview=1`, який показує тільки браузерну чернетку. Інші відвідувачі її не бачать.

**Критично:** GitHub Pages — публічна статична копія, а не захищений backend. Локальне редагування на Pages **не є публікацією** для всіх покупців і може зникнути після очищення даних браузера. Не вводьте API/GitHub токени або секрети в локальну чернетку. Драфт не передається в BB610 Market, Prom чи платіжні сервіси.

## Постійне збереження після розгортання backend

Режим `checkoutMode='backend'` показує поле для токена адміністратора. Зміна назви, опису й ціни здійснюється через `PATCH /api/v1/admin/catalog/{sku}`. Порядок зберігається атомарно через `PATCH /api/v1/admin/catalog/order` у приватній SQLite-базі.

Приклад тіла запиту на порядок:
```json
{
  "category": "lighting",
  "subcategory": "table-lamps",
  "skus": ["SKU0002", "SKU0001"]
}
```
Наведені SKU демонстраційні: сервер приймає **повний** список SKU конкретної групи; неповні, дубльовані або чужі SKU відхиляє. Доступ лише через авторизоване API.

Оригінальні ID та SKU зберігаються. Сумки MaGelle продовжують мати `storefront_visible=false` і не стають видимими від зміни порядку або тексту.

## Що ще не перенесено з BB610 Market

Захищену медіатеку із завантаженням фото, складний редактор блоків головної, менеджер категорій, імпорт/експорт товарного майстра, журнал змін, резервні копії та повну систему інтеграцій потрібно адаптувати окремо. Не варто просто копіювати 131 файл BB610 Market: частина модулів розрахована на інший бізнес та інші серверні контракти.

Домен `3dividruk.com.ua` лишається на Prom.ua; отримання реальних платежів і створення ТТН не активовані.

## Головна сторінка та медіатека (наступний етап)

- [Головна / Вітрина](../admin/homepage.html): налаштування першого екрану, вибір продукту, тексти, обкладинки категорій, вибрані картки, перестановка блоків. Базова конфігурація — `data/homepage.json`.
- [Медіатека / Фото](../admin/media.html): пошук товарів, вибір головного фото, порядок галереї. **Нові фотографії завантажувати поки не можна** без сховища й авторизації; оригінальні файли залишаються.
- Редактори використовують той самий локальний ключ `3dividruk_admin_draft_v1`, що й редактор карток. Експорт з будь-якого редактора включає всі поточні зміни.
- Для безпечного перенесення на статичний сайт: `python tools/apply_editor_draft.py export.json --check`, потім команда без `--check`, потім `python tools/build.py` та `python tools/validate.py` і перегляд Git diff перед комітом.
- Серверні ендпоїнти, підготовлені для майбутнього: `GET /api/v1/homepage`, `PATCH /api/v1/admin/homepage`. Зміна порядку фото — через авторизований `PATCH /api/v1/admin/catalog/{sku}` (тільки перестановка наявних фото).
- Жоден редактор на GitHub Pages не приймає реальне замовлення і не має прав на GitHub-репозиторій.
